# Python dependencies

The active workflow has two execution profiles:

- CPU FV generation: NumPy, SciPy, Joblib, and Matplotlib;
- GPU model training/validation: the CPU stack plus JAX with a CUDA plugin,
  Optax, `soap-jax`, Equinox, Optimistix, and tqdm.

The project does not require Warp, cuDSS, CuPy, PyTorch, or MPI for the active
scripts. JAX is used for neural-network training and automatic differentiation;
the FV labels are generated by the CPU solver outside JAX.

## Environment

Use the cluster-specific Python/CUDA modules documented in
[`PERLMUTTER.md`](PERLMUTTER.md) or [`HIPERGATOR.md`](HIPERGATOR.md), then
activate the validated conda environment:

```bash
conda activate /pscratch/sd/j/jsarnaud/conda-envs/deeprunaway-warp
python -c 'import sys; print(sys.executable)'
```

Keep the environment outside generated datasets and model runs. Do not install
dependencies into the repository during a production run.

## Required imports

Check the complete import set after installing or changing the environment:

```bash
python - <<'PY'
import joblib
import jax
import matplotlib
import numpy
import optax
import scipy
import soap_jax
import tqdm

print("JAX:", jax.default_backend(), jax.devices())
print("FP64:", jax.config.jax_enable_x64)
PY
```

Training and validation require a visible JAX GPU. Dataset generation may be
run in a CPU-only allocation. Do not treat a login-node import as evidence that
the GPU backend is usable.

## Version policy

Pin versions in the environment rather than in the repository drivers. JAX,
its CUDA plugin, and the NVIDIA driver must be a compatible set for the target
cluster. Keep a package export or environment lockfile with production runs.
The scripts enable JAX FP64 and disable memory preallocation before importing
JAX; these settings are part of the numerical/runtime contract.

## Multi-node requirements

Data/DeepONet training uses JAX multi-host initialization through Slurm and
requires:

- one visible local GPU set per node;
- one Slurm task per node;
- passwordless host reachability between allocated nodes;
- a shared filesystem for the dataset, run directory, and synchronization
  markers;
- `scontrol show hostnames` available to the launcher.

CPU FV generation uses one process per node and Joblib workers within each
process. SOAP physics training uses the same one-process-per-node JAX launch;
multi-node SSBroyden is executed on rank 0 and then broadcast.
